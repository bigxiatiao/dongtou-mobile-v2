# 洞头基层智治系统 · 移动端设计优化 Skill

> 此文件保留为 Skill 版规范归档。面向前端开发的正式交接规范已整理至根目录 [design.md](../design.md)；后续前端实现与验收以该文件为准。

> **调用目的**：优化用户现有 Figma Design 画布或 Figma Make 可运行原型，不是从零创作无关页面。
>
> **独立规范**：本文独立包含设计 Token、组件尺寸与交互规则、页面垂直节奏及验收要求；无需读取任何外部 UI 组件库规范，也不得回答“组件使用某外部库默认值”来规避具体设计决策。
>
> **优先级**：用户本轮明确要求 > 本文强制设计规则 > 已有合规组件和变量 > 本文可调整建议；保留实际业务内容始终是强约束。

> **修订日期**：2026-10-28。以用户确认意见及 [Figma 规范优化版](https://www.figma.com/design/3ybszrjcEF87fJxRljUc6n?node-id=76-1295) 为依据。本轮仅更新规范，未同步修改设计稿或运行时样式；历史页面反馈规则暂不纳入本轮规范。

## 1. 触发范围与安全边界

用户要求“优化选中的页面 / 设计稿 / 移动端 UI / 交互 / 列表 / 排版 / 间距 / 组件一致性 / 视觉层级”时使用。

- 默认仅作用于用户选定的 Frame、页面或明确目标。不擅自批量改动整个文件。
- 先分析再优化：保留所有原有标题、字段、筛选项、状态、操作入口、业务流程及信息可访问路径。
- 不虚构人员、地理位置、统计指标、处理结果、日期或权限；无法确认的业务条件保持原逻辑并报告。
- 优先复制原 Frame 生成“原名称 / 优化版”，供前后对比；用户要求原地编辑时尊重指令并尽可能保留可回退版本。
- Figma Design 保持可编辑的 Text、Frame、Auto Layout、组件和变量；Figma Make 保持 React 原型可运行、交互逻辑有效。绝不使用整页图片伪装可编辑结果。

## 2. 先完成诊断，不直接批量美化

1. 查看当前界面、图层树、真实文案、已有组件/变量、交互与页面关系；识别当前操作环境是 **Figma Design** 还是 **Figma Make**。
2. 建立内容清单：导航、模块标题、字段、列表、筛选、状态、按钮、附件、详情和跳转路径。优化后逐项对应，不能丢失。
3. 标注当前信息层级：页面级、模块级、分组级、字段级、状态与操作级；明确哪些应靠近、哪些要拉开距离。
4. 列出最主要的 3–5 个问题，优先修复多层嵌套、字段可读性差、主操作不清、间距层级混乱、控件不一致等 P0/P1 问题。
5. 只在原有业务框架内重排信息。多层列表优先转为：一级可扫读列表 + 分组、折叠/展开、逐级查看或底部详情；原有父子关系和字段必须仍然可以访问。

## 3. 关键规则：纵向间距必须呈现层级和节奏（MUST）

### 3.1 当前设计稿基线

2026-10-28 只读核对目标分区的 12 个页面：所有“页面正文”容器实际 `itemSpacing=12px`，四边内边距为 16px；有多个正文模块的页面，相邻模块边界的实际距离均为 12px。部分图层仍命名“模块间距32”，但名称不代表实际属性，禁止据此恢复为 32px。

以实际 Auto Layout 属性和相邻内容边界为依据，不把旧规范的 24/32/40px 模块节奏套回当前设计稿。页面外层、卡片内部、字段和表单分别定义职责；不同职责允许同为 12px，不要求每一级间距严格递增。

### 3.2 按内容关系使用间距

| 内容关系 | 当前默认值 | 用法 |
| --- | ---: | --- |
| 标题与说明、记录内连续文字 | 4px | 同一信息单元紧密关联 |
| 字段组内部、标签到控件 | 8px | 如联系方式、转移依据、表单标签 |
| 模块标题到内容 | 12px | 如“我的任务”标题到任务卡片组 |
| 同组纵向卡片、正文业务模块 | 12px | 12 页正文统一采用此值 |
| 卡片内部普通内容组 | 12px | 概况、分组详情卡片 |
| 卡片内部独立段落、表单项或表单行之间 | 16px | 现场办理、对象依据、联系信息 |
| Tabs 到内容 | 16px | 搜索结果、门址详情导航 |
| 操作按钮之间 | 8px | 同一操作组 |

卡片内布局按内容选 12px 或 16px；字段组内部仍保持 4px 或 8px，不将所有嵌套容器改为同一个 gap。

### 3.3 页面与卡片内边距

- 页面正文四边 16px；屏幕安全区单独计算。
- 普通业务卡片四边 16px；嵌套说明块 12px；重点概况卡片可用 20px，如安置点概况。
- 横排任务卡片组使用 8px 或 12px：基层首页当前为 8px，部门首页当前为 12px，按容纳内容保留差异。
- 图标与文字通常 4px 或 8px；顶栏已有紧凑组合可保留 3px 图文间距、6px 垂直内边距等局部值，不推广为正文默认间距。
- 当前层级列表中的 24px / 48px 左内边距属于逐级缩进，不属于纵向模块节奏。
- 空状态可使用 32px 留白；较大留白仅服务具体场景，不作为所有模块的默认间距。

### 3.4 页面节奏示例

```text
页面正文（内边距16）
  页面导航
    ↓ 12px
  概况卡片（内边距16，内部内容组12或16）
    标题 → 4px → 说明
    字段组内部8px
    ↓ 12px
  现场办理卡片（内边距16）
    标题 → 16px → 表单项
    表单标签 → 8px → 控件
    表单项之间16px
    ↓ 12px
  办理经历卡片（内边距16，标题到内容12）
    记录内部文字4px
    ↓ 12px
  操作组（按钮之间8px）
```

### 3.5 布局实现与核对

- 核对有效间距，避免父级 gap 与子级 margin 重复叠加。边框、系统安全区、文本自然高度、触控区不混入间距 Token。
- 顶栏背景与正文的现有叠放属于头部组合，不据此推导负间距 Token；横向两端对齐优先使用布局分配空间，不把固定坐标差当作通用 gap。
- 不用人为插空格、空图层制造布局；使用 Auto Layout 或 Flex/Grid，字段和操作按可见边界进行光学对齐。
- 保留当前设计稿的局部例外并明确所属组件，不再以旧的唯一刻度表批量覆盖现有布局。

## 4. 字体排版（MUST）

- 字体：`PingFang SC` → `Noto Sans SC` → `Noto Sans` → `sans-serif`。缺字体必须如实报告实际回退。
- **所有文字行高 Auto、字距 0**。Figma Design 中设置 Auto；Figma Make 的 CSS 使用 `line-height: normal; letter-spacing: 0;`，不能使用无效的 `line-height: auto`。
- 文本自然撑高容器；**不得通过固定行高或统一 16px 间距来弥补排版结构错误**。

| 类型 | 大小 / 字重 |
| --- | --- |
| 关键统计数字 | 28px / 600 |
| 页面标题 | 20px / 600 |
| 模块标题 | 18px / 600 |
| 卡片标题 | 16px / 500–600 |
| 默认正文 | 14px / 400 |
| 正文强调 | 14px / 500–600 |
| 辅助文本 | 12px / 400 |
| 小按钮文字 | 12px / 500 |
| 中按钮文字 | 14px / 500 |
| 大按钮文字 | 16px / 500 |

所有可见文字最小 12px，不再使用 10px 微型标签。不再硬性限制全项目只能有 3–4 种字号；字号必须对应表中的明确角色，同类内容保持一致，优先通过字重、颜色和留白建立层级。除特别声明外所有文字都使用 Auto 行高和 0 字距。重要业务信息不得无提示截断；卡片标题通常最多展示 2 行，必要时可展开查看全文。

## 5. 颜色、圆角与表面（MUST）

整体采用蓝色主调、清晰现代的政务风格；以本节语义色作为设计基线，代码中旧色阶后续按语义映射，不再要求沿用旧色阶体系。

| 语义 | 色值 |
| --- | --- |
| 主要操作 / 选中 | `#1677FF` |
| 小字号主按钮背景 / 浅蓝按钮文字 | `#0958D9` |
| 小字号主按钮按下 | `#003EB3` |
| 主色浅背景 / 浅蓝按钮背景 | `#E6F4FF` |
| 浅蓝按钮按下背景 | `#BAE0FF` |
| 成功 | `#52C41A` |
| 预警 | `#FAAD14` |
| 错误 / 危险 | `#FF4D4F` |
| 页面背景 | `#F5F5F5` |
| 卡片/弹层 | `#FFFFFF` |
| 一级文字 | `#1F1F1F` |
| 二级文字 | `#595959` |
| 三级文字 | `#8C8C8C` |
| 禁用文字 | `#BFBFBF` |
| 控件边框 | `#D9D9D9` |
| 分割线 | `#F0F0F0` |

- 状态必须有明确文字，颜色只做辅助。普通文字对比度 ≥4.5:1；大字（常规字重至少24px或粗体至少约18.7px）及关键图形目标 ≥3:1。
- 保留品牌蓝 `#1677FF`；12/14/16px 白字实底主按钮使用 `#0958D9`，按下使用 `#003EB3`。白字配 `#0958D9` 对比度约 6.16:1，避免直接把品牌蓝当小字号白字背景。
- 三级文字 `#8C8C8C`、成功/预警/危险色是语义色，不自动等同于合格的文字颜色。实际背景上的可见文字须单独核对，不足时加深前景色。危险按钮可使用 `#CF1322` 背景配白字，按下 `#A8071A`；不能用亮红底白字替代核对。禁用态保持可识别。
- 普通控件边框及分隔线 0.5px；焦点轮廓 2px，选中指示条 2px。图标描边另按第7节的 1.25px。细线按设备像素渲染，不声称任何设备都呈相同物理宽度。
- 圆角按组件分别定义：按钮 4px、搜索栏 6px、普通输入 8px、业务卡片 12px、底部弹层和弹窗 16px、胶囊 9999px。**禁止一键统一全部圆角**。
- 嵌套表面的圆角根据外层圆角与内边距协调，避免内外轮廓不协调；不以装饰性圆角替代内容分组。
- 卡片通常无阴影；确有浮层时使用 `0 2px 8px rgba(0,0,0,.06)`，弹窗可用 `0 8px 24px rgba(0,0,0,.12)`。
- 不使用夸张渐变、大面积彩色描边与厚重投影掩盖内容层级。

## 6. 组件独立默认规格（MUST）

**下表已写入要执行的值和行为，不用查询外部 UI 组件库默认参数。优先复用当前文件或项目中已符合规则的基础组件。**

| 组件 | 默认样式 | 行为与布局 |
| --- | --- | --- |
| 按钮 | 大48px/16px，中40px/14px（默认），小32px/12px；字重500；圆角 **4px** | 默认次级操作使用 LightBlue；主按钮实底；各尺寸触控区至少44px；状态完整 |
| 图标按钮 | 图标大小随同排内容高度调整，描边1.25px；触控区至少44×44px | 图标颜色继承语义色；必须有文字可访问名称 |
| 搜索栏 | 可视高 **32px**；圆角 **6px**；左内边距 8px | 交互行/热区 ≥44px；清空、取消、筛选状态明确 |
| 单行输入 | 最小交互行高 44px；横向内边距 12px；有边框时圆角 8px | 默认/焦点/填入/错误/禁用；多行内容自然增高 |
| 表单项 | 标签到控件 8px；错误说明距离控件 4px；相邻表单项 16px | 必填项标题后加红色 `*`；非必填不标“选填”；标记依实际校验规则，不自行改变必填性 |
| 列表行 | 最小交互行高 56px；左右内边距 16px；主次文案间 4px | 多行自然撑高；分组内可用细分割线 |
| Tabs / 分段导航 | 导航高 44px；选中指示条 2px | 选中清晰，空间不足可横向滚动；内容区与导航间 16px |
| 自定义顶栏 | 高 44px（安全区另计）；标题 18px/600 | 两侧操作热区 ≥44px；不重复绘制状态栏 |
| 自定义底栏 | 高 56px + 底部安全区 | 选中态明确；不遮挡正文与固定按钮 |
| 业务卡片 | 白底、圆角 **12px**、内边距 **16px**、无阴影 | 标题-说明 4px、字段行 8px、卡内段落 16px、同组卡片间 12px |
| 状态标签 | 字号 12px、圆角 4px、水平内边距 8px、垂直 4px | 颜色与状态词同时出现 |
| Dialog | 白底圆角 16px；左右距屏边至少 16px | 确认/取消清楚，危险操作使用明确后果文案 |
| 底部弹层 | 顶部圆角 16px；左右内边距 16px；安全区另计 | 可关闭、可滚动、有返回或取消路径 |
| 空状态 | 说明文本 12/14px；周围留白 32/48px | 不造假，允许重试或调整筛选 |
| 反馈消息 | 字号 14px；语义反馈清晰 | 重要错误不靠瞬时消息承载全部解释 |

### 6.1 统一 Button 组件

- 统一使用一个 Button 组件，不另建独立的危险按钮组件集。
- `Kind`：Primary / LightBlue / Danger / Neutral；`Size`：Large / Medium / Small；`State`：Default / Pressed / Loading / Disabled。
- LightBlue 为默认次级操作样式，浅蓝底、深蓝文字，无需额外描边；Neutral 保留为可选变体，不再作为默认。指定优化版范围原 Neutral 实例已要求替换为 LightBlue，不据此删除组件库变体。
- Primary 的普通文字背景采用第5节的深蓝；Danger 使用明确危险语义；Disabled 使用页面浅灰底及禁用文字色，Loading 阻止重复提交并提供可访问的忙碌状态。
- 页面主流程按钮可保留纯文字；其余操作按钮使用 Tabler 图标＋文字。返回、关闭等已有纯图标导航控件按图标按钮规则保留，必须有可访问名称。
- 组件提供文案、是否显示图标、图标替换属性，切换类型时保留文案、尺寸和状态。

本节为项目固定默认规格，不代表所有组件必须同样宽、同样高、同样 gap。组件内部使用第 3 节的**关系式间距**，不能只使用“统一 16px”。

## 7. 图标资源（MUST）

- 延续项目已选定的唯一图标源 **Tabler Icons**。优先复用 Figma 文件或 React 工程中已有的合规素材/组件。
- 优先 **Outline**；**不固定20px**，图标大小根据同排文字或内容的实际高度及视觉重量调整，垂直光学居中；同角色与同类控件保持一致。**描边统一1.25px**，Web 使用 `currentColor`。必须按照操作语义选择、核对真实资源，不可编造图标名称。
- Figma Design：使用现有合规组件实例，或官方可编辑矢量资产，不自行画近似 SVG 代替。
- Figma Make / React：优先使用已安装的 `@tabler/icons-react`；缺失时按项目包管理器安装，确认实际组件导出；不得重复制造一套图标封装。
- 禁止 Emoji、Unicode 图标、未经确认的自绘 SVG 或混用其他图标体系。没有合适图标时先说明缺口再商量。
- 视觉尺寸与操作热区分离；紧凑返回图标不放大成宽大按钮，但实际热区至少44×44px。纯图标按钮在 Make 中有 `aria-label` 或同等可访问名称，装饰图标 `aria-hidden`。
- 头部科技感矢量插画可作为内容资产，不替代功能图标体系。彩色入口插画属于可选内容资产，单独定义、不能混入 Tabler 功能图标组件；既有插画保留不代表新增另一套功能图标库。
- React 复用 `src/components/AppIcon.jsx` 的 AppIcon 与显式导入注册表；HTML 模板通过 `data-tabler` 交给同一渲染层，避免全量动态导入。

## 8. 移动端业务模式与结构优化

- 页面画布以 375px 为默认基准；另检查 320/360/390/430px，页面实际宽度流式自适应。
- 首页沿用当前内容框架和顺序，正文模块间距12px；标题到内容12px，卡片内关系按第3节细分，不强制插入40px呼吸段。
- 事件列表：导航 → 搜索/筛选 → 分组或卡片列表；正文区块及同组卡片间12px，元数据组内部8px。
- 事件详情：概要与状态 → 核心字段 → 处置记录 → 附件 → 操作；业务卡片之间12px，内部字段组8px，卡内独立段落12或16px。
- 多层嵌套：优先把二级/三级内容移入按需展开区、详细页面或底部弹层；父子关系、原始字段和操作路径一项也不能丢。
- 办理经历采用纵向时间轴，保留真实记录、时间顺序和展开操作；记录内部文字4px，时间轴与标题等相邻内容按卡内12px组织，不制造记录。
- 不允许凭空增加虚构统计、操作记录、用户信息、时间线或空造的业务入口。

## 9. 在不同 Figma 环境实施

### 9.1 Figma Design（原生画布）

1. 尽量在原 Frame 旁建立可比较的“优化版”，保持原始内容。
2. 使用真实可编辑的 Text、Frame、Auto Layout、组件实例、Variables / Styles；同语义变量优先复用，不重复建立。
3. 对每个纵向 Auto Layout 赋予明确职责：`页面模块 gap=12`、`模块标题-内容 gap=12`、`卡片列表 gap=12`、`卡片字段 gap=8`、`标题-说明 gap=4`，而不是给所有垂直容器设置 16。
4. 按组件规则设置视觉尺寸、圆角；Figma 文本属性需直接显示 Auto 行高、0 字距；利用 Hug contents / Fill container 避免固定高度裁切文本。
5. 复查层级顺序、屏幕边距、长文字、下拉内容、固定操作遮挡；可编辑性不下降。

### 9.2 Figma Make（React 原型）

1. 在现有工程基础上修改，不重新生成无关的新项目；优先复用已存在的页面组件和事件状态。
2. 把不同层级的纵向间距写成独立的语义 Token，例如 `--gap-field:8px`、`--gap-card-list:12px`、`--gap-page-section:12px`，不可全局仅定义 `--gap:16px`。
3. 通过 Flex/Grid 表达结构，布局自适应；文字使用 `line-height:normal; letter-spacing:0`，不固定 375px 页面宽度。
4. 实际试用搜索、筛选、折叠/展开、返回、弹层、按钮的 Disabled/Loading 等状态；未接入后端时准确标注演示逻辑。
5. 不声称编辑 Make 源码等同于已经更新 Figma Design 中的原生图层、组件或变量。
